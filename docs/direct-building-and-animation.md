# Direct building, public venues and skeletal animation

The room is the editing surface. Enter **Build & buy**, select or drag a furnishing in the house, and release on a valid tile. The green/red footprint and ghost use the authoritative housing validator, including budget, entrance access, partitions, reachable floor and object approaches. A preview never changes funds or furniture. Invalid drops retain the original object. R rotates, Escape cancels, WASD moves the preview, and Enter places. Selecting an owned item exposes storage/sale; stored items can be placed again without buying them. Walls, door openings and removal use the same rendered floor edges. Pan mode and two-finger camera gestures take priority over editing.

Build mode is a game-state command, validated on both local and server paths. All housing edits require it. It can be entered only at the resident's own home while idle. Walking, object use, travel, jobs and pet care are blocked during editing; queued/autonomous actions wait. Finish building resumes play, where an object click opens activities and a drag pans the camera. Background persistence continues through the existing projected command FIFO; an edit does not introduce a save/input lock.

Every new household gets an essential 1×1 shower. The source move-in budget and purchased inventory remain intact. Older homes receive a one-time complimentary fixture when idle; placement is validated, and the owned fixture goes to storage if a packed legacy floor cannot accommodate it. It costs and resells for zero, is not in the purchase catalogue, and the server rejects attempts to buy another essential fixture.

All five cities now have a library, in addition to their café, workplace, park and station. Station index/identity remains stable. Public spaces use authored 12×12 plans with service/seating, work/meeting, or stacks/reading areas and clear circulation. They never derive their plan from a household starter package. Each has at least 20 furnishings, purpose-specific interactions and a persistent local contact. Six original commercial sprites/exterior assets have preserved alpha; prompts and hashes are in `public/art/venues/prompts.json`.

Human animation uses a Three.js SkinnedMesh bound to 26 named hierarchical bones with per-vertex skin indices/weights. Spine, head/jaw, arms, elbows, hands/fingers, hips, knees and feet have distinct motion. Every game ActionKind has a skeletal pose cycle, along with walking/idle, validator/grifter challenges and pet care. NPCs and online visitors use the same renderer. Action transitions blend over 180ms; reduced motion holds a readable action pose. The Three renderer is shared by residents in each scene and renders into Phaser textures. A CPU projection of the same weighted mesh supports devices without WebGL2. This preserves the existing isometric world, collision, camera and NFT-derived identity while allowing articulated bodies rather than rotating a standing picture.

Bathing moves the resident into the shower, animates scrubbing and weight shifts, blurs the resident texture, adds a frosted enclosure, and emits water and vapor drifting beyond the cubicle. Privacy is tied to the bathing action, never to save/network status. Clothes changes, cloth/hair physics and a free 3D camera are outside this implementation; the procedural character mesh remains stylized and needs further art refinement to reach the supplied reference's fidelity.

The skinning API follows [Three's SkinnedMesh documentation](https://threejs.org/docs/pages/SkinnedMesh.html); the bone hierarchy uses [Bone](https://threejs.org/docs/pages/Bone.html). Runtime/test details are in `src/world/skeleton`, `tests/skeletal-animation.test.ts`, `tests/build-mode.test.ts` and the direct canvas browser scenarios.

Validation is local. External requests are blocked in browser tests. No live database, wallet or contract writes, push or deployment are part of this change.

## Local verification

110 unit tests and TypeScript/lint pass. Tests cover real weighted vertex deformation for every action, identity/migration invariants, engine-enforced Build mode, preview economics and delayed-save ordering. The 1,969-source-household audit verifies a reachable shower, preserved move-in budgets, valid layouts and 216 available art assets. Focused browser checks pass for direct drag/reject/cancel/reload, real mobile touch placement plus pinch/Pan separation, library entry/reading/reload, physical bathing privacy, sleep, furniture storage, café/NPC visits, travel and connected partitions. The no-WebGL2 browser check verifies the CPU weighted-mesh fallback and walking. All 32 distinct browser scenarios pass across the full run and corrected expectation/storage-flush rechecks. All 14 local Solidity tests pass. The Node 22 production build passes. Six venue-asset hashes match the production output (677,932 bytes total). A browser smoke against the actual built files verifies skeletal rendering, Build entry/exit, shower blur and library entry without page errors; the enlarged café/library checks pass. Large wallet/vendor/Phaser and lazy skeleton chunk warnings remain.
